# PARA Method

Tiago Forte's filing system: four top-level buckets covering everything, ordered by **actionability, not topic**.

- **P**rojects — outcomes with a deadline: "ship the RAG assistant," "write Q3 review." Active by definition; a project without a next action is stuck, and stuck projects get audited.
- **A**reas — ongoing responsibilities with a standard, no end date: health, finances, the vault itself.
- **R**esources — topics of interest with no responsibility attached: notes on [[what-is-rag]], [[zettelkasten]], reading notes.
- **A**rchives — inactive items from the other three, kept for reference.

## The one idea that matters

The distinction between Projects and Areas is *outcome vs. standard*. "Learn enough RAG to build the assistant" is a project (it ends); "keep my knowledge base useful" is an area (it never does). Filing by topic instead — work, personal, reading — hides exactly this difference, and stale projects blend into permanent areas unnoticed.

## In my vault

PARA maps onto the folder layout in [[vault-organization]] (projects/, areas/, resources/, archive/ plus an inbox). The mapping is loose on purpose: PARA is a decision procedure for "where does this go?" — the answer is always "the most actionable bucket this belongs to."

## The failure mode

PARA with no review becomes four junk drawers. The weekly sweep — see [[weekly-review]] — is what keeps Projects honest and moves dead ones to the archive. The system is the review, not the folders.
