# Inbox Zero

Merlin Mann's method, widely misread. Zero is not "no mail exists" — it's **nothing left undecided**. The inbox is a processing queue, not a storage system and not a to-do list.

## The pipeline

For each item, in order, exactly one of:

1. **Delete** — the default. Most email deserves it.
2. **Delegate** — if someone else should do it, forward with a clear ask.
3. **Respond** — if it takes under two minutes, reply now. Waiting costs more than doing.
4. **Defer** — needs real work: turn it into a task in the system ([[para-method]] project or next action), then archive the mail. The task list owns it; the inbox doesn't.
5. **Archive** — keep for reference, out of the inbox.

## The mindset shift

The question per message is not "have I dealt with this?" but "**what is the decision?**" Once decided — even if the decided action is scheduled elsewhere — the mail leaves. An inbox of 4,000 undecided items is a to-do list you can't read.

## Limits

Zero is a processing state, not a permanent achievement — the inbox refills by design. The failure mode is processing mail all day: batch it two or three times daily, outside [[deep-work|deep blocks]]. Mail is the quintessential shallow work; it gets scheduled, not reacted to.
